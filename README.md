# Full-Stack Demo (Vuetify + FastAPI)

## Project Goal
This project serves as a comprehensive demonstration of full-stack development capabilities, integrating modern web technologies with AI/LLM functionalities. It is designed to showcase proficiency in Python/FastAPI backend, Vue.js/Vuetify frontend, AI/LLM platform development, containerization (Docker), and cloud-native deployment readiness, aligning with the requirements for a Senior Software Engineer role.

This POC also demonstrates end-to-end DevOps ownership — CI/CD with GitHub Actions, containerization, Kubernetes readiness, and a production-grade observability stack (OpenTelemetry + Prometheus + Loki + Tempo + Grafana).

## Key Features
- **Full-Stack Development**: Vue 3 + Vuetify frontend, FastAPI Python backend, modular architecture.
- **AI/LLM Platform**: Integration with multiple LLM providers (OpenAI, Anthropic, Local), streaming chat, RAG pipeline.
- **Secure Authentication**: JWT-based auth with access/refresh tokens, protected endpoints, admin guards.
- **Database Management**: PostgreSQL with SQLAlchemy ORM, Alembic for schema migrations.
- **Containerization**: Multi-container Docker setup with `docker-compose`, backend entrypoint runs Alembic migrations automatically.
- **Cloud-Native Readiness**: CI/CD workflows configured for Azure/GCP deployment.
- **API Design**: Versioned REST API (`/api/v1`), OpenAPI/Swagger docs, clear dependency injection.
- **Asynchronous Processing**: Dramatiq workers for background LLM jobs.
- **Testing Strategy**: Pytest (backend), Vitest (frontend) with CI integration.
- **Code Quality**: TypeScript, Pydantic validation, Ruff/linting, pre-commit hooks.

## Development Methodology

This project adopts a **modular, domain-driven development approach**, emphasizing Test-Driven Development (TDD) principles to ensure high code quality, maintainability, and scalability. This methodology is applied consistently across both frontend and backend.

### Modular Development
- **Backend (`backend/app/modules/`)**: Organized into distinct, feature-specific modules (e.g., `ai`, `auth`, `system`). Each module encapsulates its own API endpoints, services, data models, and business logic, promoting clear separation of concerns and independent development.
- **Frontend (`frontend/src/modules/`)**: Structured similarly into modules, allowing for isolated development of features, reusable components, and clear boundaries for state management and API integration.

### Test-Driven Development (TDD)
- **Test-First Approach**: New features or bug fixes begin with writing failing tests that define the desired behavior. Code is then written to make these tests pass, followed by refactoring.
- **Granular Testing**: Tests are written at various levels (unit, integration) for individual functions, classes, and API endpoints within each module, ensuring comprehensive coverage and minimizing side effects.
- **Automated Testing**: Integrated Pytest for backend and Vitest for frontend, providing fast feedback loops during development and enabling continuous verification via CI/CD pipelines.

## Observability & Monitoring

This application is instrumented with a robust observability stack using OpenTelemetry to provide deep insights into its behavior, performance, and health across both frontend and backend components. This setup is crucial for proactive monitoring, rapid debugging, and maintaining system reliability in production environments.

### Key Components (Orchestrated via Docker Compose)
- **OpenTelemetry Collector**: Aggregates, processes, and exports telemetry data.
- **Prometheus**: Stores and queries time-series metrics.
- **Loki**: Centralized log aggregation system.
- **Tempo**: High-volume, distributed tracing backend.
- **Grafana**: Visualizes metrics, logs, and traces through comprehensive dashboards.

### Observability Features
- **Distributed Tracing**: End-to-end request tracing allows visibility into how requests flow through the entire system, identifying bottlenecks and latency issues.
- **Metrics**: Captures application-level and infrastructure metrics for performance monitoring, resource utilization, and health checks.
- **Structured Logging**: Ensures consistent log formats across services, enriched with trace IDs for easy correlation with traces.
- **Custom Dashboards**: Pre-configured Grafana dashboards provide real-time views of frontend performance (component render times, user interactions) and backend health (API latency, error rates, resource usage).

### Backend

The FastAPI backend is structured for enterprise-grade scalability and maintainability.

**Architecture:**
- **Core Module (`app/core/`)**:
  - `config.py`: Centralized configuration using Pydantic Settings, loading environment variables from `.env`.
  - `database.py`: SQLAlchemy engine and session management for PostgreSQL/SQLite, with a FastAPI dependency for database sessions.
  - `security.py`: Stub for JWT token creation and verification (future use).
- **API Versioning (`app/api/v1/`)**:
  - Uses `APIRouter` for versioned endpoints, mounted at `/api/v1`.
  - Health check is available at `/api/v1/health` and legacy `/health`.
  - **New:** `GET /api/v1/dashboard/stats`: Returns platform statistics (Total Users, Active Sessions, API Calls).
  - **New:** `GET /api/v1/users`: Returns a list of mock user data.
- **Middleware**: Configured with CORS to allow frontend communication (e.g., from `http://localhost:5173`).
- **Error Handling**: Global exception handlers for `HTTPException` and unhandled exceptions provide consistent JSON responses.
- **Alembic**: Database migration tool configured to manage schema changes.

**Setup & Run:**

```bash
cd backend
# Create environment and install dependencies
uv sync
# Run development server
uv run uvicorn app.main:app --reload
```

**Alembic Migrations in Docker/Podman:**

Migrations are now automatically run on backend container startup.
- The `entrypoint.sh` script executes `alembic upgrade head` before starting the FastAPI application.
- This ensures the database schema is always up-to-date upon startup.
- To generate a new migration script (after model changes): `docker compose exec backend uv run alembic revision --autogenerate -m "Description"`

Backend runs at http://localhost:8000

### Frontend

The Vue 3 frontend leverages Vuetify for a modern UI.

**Architecture:**
- **Layouts (`src/layouts/`)**: `DefaultLayout.vue` provides the main app structure, integrating the `v-app-bar`, `v-navigation-drawer`, and `<router-view />`.
- **Stores (`src/stores/`)**: Pinia is used for state management, including `theme.ts` for dark/light mode persistence and `auth.ts` for user session.
- **API Integration (`src/composables/useApi.ts`)**: An Axios-based composable simplifies API calls, handles base URL configuration, and error interception.
- **Views (`src/views/`)**:
  - `Dashboard.vue`: Displays key metrics and user data fetched from backend APIs. Handles loading and error states.

**Setup & Run:**

```bash
cd frontend
npm install
npm run dev
```

Frontend runs at http://localhost:5173

## Frontend Layout Architecture

The frontend uses a layout component pattern for consistent UI:

### Layout Components

- `src/layouts/DefaultLayout.vue` - Main application layout with Vuetify navigation
  - Contains `<router-view />` for route content
  - Includes navigation drawer, app bar, and theme toggle

### App.vue Pattern

App.vue must use the layout wrapper:

```vue
<template>
  <DefaultLayout />
</template>

<script setup lang="ts">
import DefaultLayout from '@/modules/layouts/DefaultLayout.vue'
</script>
```

**Do NOT** hardcode Vuetify components directly in App.vue - use layouts for consistent structure.

### Available Layouts

| Layout          | Purpose                                          |
| --------------- | ------------------------------------------------ |
| `DefaultLayout` | Main app with navigation drawer and theme toggle |

### Adding New Layouts

1. Create layout in `src/layouts/`
2. Export from `src/layouts/index.ts`
3. Update App.vue to use new layout
4. Run `npm run typecheck` to verify

### Pre-commit Check

A pre-commit hook verifies App.vue uses a layout component. Commit will fail if hardcoded content is detected.
